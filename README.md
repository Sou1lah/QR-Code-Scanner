# AMANE DZ

AMANE DZ is a QR-code safety scanner built with Expo and React Native. The mobile app is in `mobile/`. The repository also contains a legacy web/PWA app in `src/`.

The mobile app scans QR codes with the camera or from an image, shows a safety review before any action, and stores recent scan history locally.

## Features

- Scan QR codes with the rear camera or select an image from the photo library.
- Review the decoded payload, verdict, risk score, summary, and security diagnostics before acting.
- Dangerous links are blocked by the app's open action. Other links require a separate user action.
- Review and clear up to 100 locally saved scans.
- Configure dark mode, demo mode, and scanner policies.
- Analyze payloads on-device or use a backend when one is configured.

Local URL analysis uses heuristics. It is not a guarantee that a site is safe or a substitute for checking an unfamiliar destination.

Native `mobile/ios/` and `mobile/android/` projects are generated by Expo when needed and are ignored by Git. Configure native behavior in `mobile/app.json` or Expo config plugins; do not make persistent edits to generated projects.

## Requirements

All platforms require Node.js and npm.

For Android development, install Android Studio, the Android SDK and an Android Virtual Device (AVD). APK builds require JDK 17 or newer.

For local iOS development, use a Mac with Xcode, Xcode Command Line Tools, and an installed iOS Simulator runtime. An Apple Developer Program membership is not required for Simulator development. Installing the app on a physical iPhone or distributing it through TestFlight requires Apple signing and an Apple Developer Program membership.

## Install dependencies

Run these commands from the repository root:

```sh
npm install
npm --prefix mobile install
```

## Run the mobile app

### Android

Start an Android emulator in Android Studio's Device Manager, then run:

```sh
npm run android
```

This invokes Expo's local Android build and run command. The project README uses an AVD named `AMANE_Pixel_6_API_36`; use any available emulator or connected Android device.

To start Metro separately for Fast Refresh:

```sh
npm run dev
```

Press `a` in the Expo terminal to open the app on Android.

### iOS Simulator on Mac

Install Xcode and an iOS Simulator runtime. In Xcode, select Command Line Tools under **Xcode > Settings > Locations**. Then, from the repository root, open the simulator and run the native app:

```sh
open -a Simulator
npm --prefix mobile run ios
```

On Xcode 27, Apple uses Device Hub instead of the Simulator app:

```sh
open -a DeviceHub
npm --prefix mobile run ios
```

The first run generates the ignored iOS project, builds the app with Xcode, installs it in the selected simulator, and starts Metro. Keep the terminal and simulator open while editing. Saving files under `mobile/src/` updates the app through React Native Fast Refresh.

There is no root-level `npm run ios` script. From inside `mobile/`, the equivalent command is:

```sh
npm run ios
```

For an Expo development server without explicitly running the native build command:

```sh
cd mobile
npx expo start
```

Press `i` to open an iOS Simulator or `Shift+i` to select one. Press `a` to open Android.

### Side-by-side setup

On macOS, place the editor and Metro terminal on the left and Simulator or Device Hub on the right. Use the window's green button and select **Tile Window to Left of Screen** or **Tile Window to Right of Screen**. Keep the Metro terminal running so Fast Refresh can deliver code changes.

On Linux with KDE/Wayland, the Android scripts set `QT_QPA_PLATFORM=xcb`. To launch the configured emulator manually:

```sh
QT_QPA_PLATFORM=xcb emulator @AMANE_Pixel_6_API_36
```

### Simulator limitations

The iOS Simulator has no camera hardware. Use the scanner's image button and a simulator photo containing a QR code to test the scan and result flow. Test live camera scanning, torch, and actual camera permissions on a physical iPhone.

## Use the scanner

1. Open the **Home** tab.
2. Grant camera access when the operating system prompts. If access was denied, use the app's **Open Phone Settings** action to enable it, then return to AMANE DZ.
3. Center a QR code in the viewfinder, or tap the image button and select a picture containing a QR code.
4. Review the decoded payload, verdict, score, summary, and diagnostics.
5. Copy the payload, dismiss the review, or explicitly choose the available link action.

The scanner does not open a URL automatically. A payload marked `DANGEROUS` is blocked by the open action. `SAFE` is a heuristic result and does not prove a site is harmless.

The **History** tab shows recent scans and can clear all saved records. The **Settings** tab contains appearance and scan preferences. Demo Mode is off by default; enabling it displays sample payload buttons on Home.

### Camera permissions

Android and iOS request camera access at runtime. On Android, if the permission cannot be requested again, open **Settings > Apps > AMANE DZ > Permissions > Camera** and allow access. The app refreshes its camera permission when it returns from system Settings.

The Expo Camera plugin sets the camera usage description, and the Image Picker plugin sets the photo-library description in `mobile/app.json`. Do not disable camera permission on the Image Picker plugin: this previously removed the Android camera permission from the merged manifest.

## Scan analysis and configuration

By default, the app analyzes scans locally when no API URL is configured. The on-device checks include URL protocol, raw IP addresses, known shorteners, selected risky TLDs and keywords, and Wi-Fi QR security. These checks are heuristic and may produce false positives or miss threats.

When `EXPO_PUBLIC_API_URL` is set, the app can send a parsed payload to the backend's `POST /api/scan` endpoint and check `GET /api/health`. If the scan API is unavailable, the client logs a warning and falls back to local analysis.

The `Safe Browsing API` preference does not provide external threat intelligence by itself; a compatible backend must implement those checks. Avoid sending sensitive QR content to an untrusted backend.

The example mobile environment file is `mobile/.env.example`:

```dotenv
EXPO_PUBLIC_API_URL=
EXPO_PUBLIC_USE_MOCK=true
```

Set `EXPO_PUBLIC_USE_MOCK=true` only when testing demo responses. Leave it unset or set it to `false` to use the configured API or on-device analysis.

## Build and distribute Android

Build a standalone debug APK from the repository root:

```sh
npm run apk
```

The script requires JDK 17 or newer and an Android SDK. It runs Expo prebuild and Gradle, then writes:

```text
mobile/dist/AMANE-DZ-debug.apk
```

If ADB detects a connected emulator or device, the script installs or updates the APK automatically. Otherwise, transfer the APK to an Android device and install it. This is a debug build for testing, not a Play Store release.

## Build and distribute iOS

The iOS bundle identifier is `dz.amane.app`. Build profiles are defined in `mobile/eas.json`.

### iOS Simulator cloud build

This profile does not require Apple Developer signing. It requires an Expo account and installs on a Mac simulator, not an iPhone:

```sh
cd mobile
npx eas-cli@latest login
npx eas-cli@latest build --platform ios --profile preview-simulator
npx eas-cli@latest build:run --platform ios
```

For local iOS Simulator development on a Mac, use `npm --prefix mobile run ios` instead.

### Internal device preview

The `preview` profile creates an internal iOS build. Register each tester's iPhone UDID before building. Apple Developer signing is required:

```sh
cd mobile
npx eas-cli@latest login
npx eas-cli@latest device:create
npx eas-cli@latest build --platform ios --profile preview
```

Only devices included in the provisioning profile can install that build.

### TestFlight

TestFlight requires Apple Developer Program membership, an App Store Connect app record, and signing credentials:

```sh
cd mobile
npx eas-cli@latest login
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest submit --platform ios --latest
```

Do not share Apple passwords, API keys, certificates, or private signing keys in source control or chat.

## Troubleshooting

| Problem | Resolution |
| --- | --- |
| Android build cannot find Java | Install JDK 17 or newer and set `JAVA_HOME`. |
| Android SDK is missing | Install the SDK and emulator tools in Android Studio; set `ANDROID_HOME` or `ANDROID_SDK_ROOT`. |
| iOS build cannot find Xcode tools | Open Xcode and select Command Line Tools under **Settings > Locations**. |
| No iOS simulator is available | Download an iOS runtime in Xcode Settings, then run `xcrun simctl list devices available`. |
| iOS Simulator cannot scan a QR code live | Expected; the simulator has no camera. Select a QR image or test on a physical iPhone. |
| Camera remains unavailable after denying permission | Open the device's system Settings, enable Camera for AMANE DZ, and return to the app. |
| Backend is unreachable | Check `EXPO_PUBLIC_API_URL` and the backend's `/api/health` endpoint; local scans continue using the on-device engine. |
