01 · App mapMeet the screens

One app, three tabs

AMANE DZ is an Expo / React Native app in mobile/. It opens on Home, the QR scanner. History and Settings are two tabs in the same app; the older browser/PWA in src/ is separate.

Think of a QR code as a tiny note. The camera reads its text; AMANE shows that text and a risk review. It does not silently open the link.
TabWhat you do there
HomeScan with the rear camera, turn on the torch, or choose a QR image.
HistoryReview up to 100 saved payloads and verdicts on this device.
SettingsChoose theme and risk preferences, see Demo Mode and backend status.

Permission: the normal path

  1. Tap Allow Camera on Home.
  2. Approve the Android system prompt while using the app.
  3. If permission was denied, use Open Phone Settings, allow Camera, then return to the app.
Emulator camera tip: a virtual camera may show a blank scene or have no usable torch. Use the gallery button for a predictable QR test; use a real phone to verify physical camera behavior.

What is inside the QR?

parsePayload trims the text and classifies it:

Starts with…ClassExample use
https:// or http://URLWebsite address
WIFI:WIFINetwork name and security type
Anything elseTEXTPlain text or other content

Parser: mobile/src/lib/parsePayload.ts. It extracts Wi-Fi fields S (SSID), T (authentication) and P (password) for the request.

The preview protects the next step

The sheet shows verdict, score, summary, decoded text, diagnostics and destination. Copying is separate from opening. A payload marked DANGEROUS is blocked by the open action; other links still require a deliberate tap.

  return
}

AMANE DZ · APP GUIDE05
05 · API & risk analysisWhat the app sends and what it does not promise

Where does a scan get checked?

For a decoded QR value, the service chooses one of three paths. The app always has a local path, so a configured server is optional.

Mobile request shape

POST {EXPO_PUBLIC_API_URL}/api/scan
Content-Type: application/json

{
  "raw": "https://example.com",
  "type": "URL",
  "settings": {
    "urlShortenerUnfurl": true,
    "blockInsecureHttp": true,
    "safeBrowsingApi": true
  }
}

For WIFI, parsed data also includes wifi: { ssid, authentication, password }. The server should return a ScanResult: verdict, score, summary, diagnostics and resolvedUrl.

Local fallback is a heuristic

The built-in checks look for HTTP, selected shorteners, raw IP addresses, chosen high-risk TLDs/keywords, and open Wi-Fi profiles. This is not a live reputation lookup.

Important switches

  • EXPO_PUBLIC_USE_MOCK=true chooses demo service responses.
  • EXPO_PUBLIC_API_URL enables backend calls. Without it, scans use local analysis.
  • The Settings Safe Browsing switch is sent as a preference; an API must implement the actual lookup.
Health indicator detail: with no API URL, checkApiHealth() returns without making a request. Settings then treats that resolved result as “connected”; this status is not proof that a server was contacted.

Mobile API client: mobile/src/services/api.ts · payload type: mobile/src/types/api.ts. Root docs/API_CONTRACT.md documents the older web app config; mobile uses the EXPO_PUBLIC_* variables above.

06 · Android emulatorInstall and create a virtual phone from a terminal

Set up the Android simulator

An emulator is a virtual Android phone on your computer. It is useful for layout and app-flow testing; its camera is simulated, so use a physical phone for final camera checks.

Before you start

  • Linux computer, Node.js/npm, and JDK 17 or newer.
  • Enough disk space for Android SDK packages and one system image.
  • Android CLI (current official option) or Android SDK Command-Line Tools.

Current Android CLI route

  1. Install Android CLI by following Google’s official setup. Ensure android is on your PATH: command -v android.
  2. Install an emulator, platform tools, and an API 36 Google APIs system image (the project README names an API 36 Pixel 6 AVD):
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

If your SDK is elsewhere, change ANDROID_HOME. Put these exports in your shell startup file if you want them in every terminal.

android sdk install emulator platform-tools platforms/android-36 \
  build-tools/36.0.0 system-images/android-36/google_apis/x86_64
android emulator create medium_phone
android emulator list
android emulator start medium_phone

The first system-image download is large. Follow any license prompts. Android CLI can list profiles with android emulator create --list-profiles; the exact AVD name may differ from the project’s sample Pixel name.

Compatibility route: SDK Command-Line Tools

If you already installed the traditional Android SDK tools, these commands still work. Android’s current docs recommend Android CLI for new setups; sdkmanager is now deprecated in favor of android sdk.

sdkmanager --install "platform-tools" "emulator" \
  "platforms;android-36" "build-tools;36.0.0" \
  "system-images;android-36;google_apis;x86_64"
sdkmanager --licenses
avdmanager create avd -n AMANE_Pixel_6_API_36 \
  -k "system-images;android-36;google_apis;x86_64" -d pixel_6
emulator -avd AMANE_Pixel_6_API_36
Use the project’s existing AVD if it is already created: emulator -list-avds lists names. This repo’s README refers to AMANE_Pixel_6_API_36. Check that Android finished booting with adb devices.

Official references: Android CLI, SDK commands, and emulator commands.

Start the app once

  1. Start the AVD in one terminal: emulator -avd AMANE_Pixel_6_API_36.
  2. From the repository root, run npm install and npm --prefix mobile install the first time only.
  3. Run npm run android. Expo builds/installs the Android development app and opens it on the connected emulator.

Everyday editing loop

# Start the development server from the repo root
npm run dev
# In the Expo terminal, press a to open Android
What is changing? For ordinary screen edits, Metro sends updated JavaScript to the running app; you usually do not rebuild. Changes to native configuration or native dependencies require another native build with npm run android.

Tile the two windows

Place the editor on one half of the desktop and the emulator on the other. On many Linux desktops, Super + Left and Super + Right snap windows; KDE/GNOME shortcuts can differ. Resize the emulator to keep the whole phone visible. On KDE/Wayland, the repo’s scripts already set QT_QPA_PLATFORM=xcb.

If something does not work

What you seeTry this
Camera permission card remainsTap Allow Camera, approve the Android prompt, or open Phone Settings and grant Camera. Return to Home.
Emulator camera cannot see a QRUse the gallery button with a clear QR image; check live camera on a physical phone.
QR image reports no codePick a sharp, fully visible, uncropped QR image.
Android build cannot find Java or SDKUse JDK 17+, install Android SDK packages, and configure JAVA_HOME / ANDROID_HOME.
Backend is unreachableCheck EXPO_PUBLIC_API_URL and /api/health. The scanner falls back to local heuristics when no usable response is returned.
Good first test: enable Demo Mode in Settings, return to Home, and tap one of its sample payload buttons. Then inspect the preview and open History. The screen buttons are sample inputs; service mock responses are controlled separately by EXPO_PUBLIC_USE_MOCK=true.
Keep expectations realistic: local checks look for suspicious patterns; they cannot prove a link is safe. Demo Mode is for learning the flow, not a live security test.
